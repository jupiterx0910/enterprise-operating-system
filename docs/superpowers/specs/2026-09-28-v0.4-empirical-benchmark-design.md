# v0.4 Empirical Benchmark Design / 实证 Benchmark 设计

## Goal / 目标

Turn Enterprise Operating System from a reasoning framework with synthetic/adversarial cases into an empirically testable Agent Skill whose incremental value can be measured across models and public enterprise cases.

把 Enterprise Operating System 从“有方法论、有合成/对抗案例”的 Skill，升级成一个能够通过真实公共企业案例和模型 A/B 实验验证增量价值的 Agent Skill。

## Core question / 核心问题

> **Does installing Enterprise Operating System make the same model reason better about enterprise problems?**
>
> **同一个模型，安装 EOS Skill 后，企业经营推理是否显著变好？**

Primary paired conditions:

- `NATIVE` — model receives the benchmark prompt without EOS.
- `EOS_ENABLED` — same model/runtime/case snapshot with the canonical EOS Skill loaded.

## Primary metrics / 主指标

1. Mean Score — 0–12 using the existing six-dimension rubric.
2. Hard-Fail Rate — proportion of runs triggering a benchmark hard failure.
3. Skill Lift — `EOS_ENABLED mean − NATIVE mean`.
4. Hard-Fail Reduction — `NATIVE hard-fail rate − EOS_ENABLED hard-fail rate`.
5. Decision Completeness — evidence, owner, authority, resources, deadline, metric, review/reversal.
6. Coverage — completed cases / required cases.

Raw model capability and EOS effectiveness are separate questions.

## Benchmark tracks / 测试轨道

### Track A — Synthetic & adversarial

Use the existing 15 benchmark cases to test whether the model resists common enterprise reasoning shortcuts.

### Track B — Public real-world

Use source-grounded evidence packets based on attributable enterprise events.

Initial cases:

1. Wells Fargo sales-practice incentive failure.
2. Target Canada market exit and operating-model failure.
3. Uber 2017 culture/governance reset.
4. Equifax 2017 breach and accountability structure.
5. Boeing 737 MAX design/certification governance failure.

These are reasoning-process tests, not historical-trivia tests.

## Provenance contract / 来源协议

Every real-world case records:

```yaml
id: ""
type: real-world
source_class: public-official | public-company
known_outcome_case: true | false
evidence_cutoff: YYYY-MM-DD
sources:
  - title: ""
    publisher: ""
    published: YYYY-MM-DD
    url: ""
```

Rules:

- Prefer primary and attributable public sources.
- Separate source facts from benchmark inference.
- Do not invent motives or causal claims.
- Preserve material uncertainty and competing explanations.
- Public known-outcome cases are not contamination-resistant.

## Run contract / 运行协议

Each run records benchmark version, skill commit, case snapshot, condition, model/provider/version, reasoning effort, tools, temperature/seed when exposed, system prompt hash, timestamps, trial number, and evaluator method.

A run is not leaderboard-eligible unless raw outputs and per-case scorecards are preserved.

## Leaderboard tiers / 榜单等级

### Candidate

- Paired NATIVE and EOS_ENABLED conditions.
- One trial per required case per condition.
- Complete manifests, raw outputs, and scorecards.

### Verified

- Same model/version, tools, reasoning effort, runtime policy and case snapshot.
- At least 3 trials per case per condition.
- Full raw outputs and scorecards preserved.
- Hard-fail flags reviewed.
- At least one independent human review.
- Disputed cases require adjudication.

Primary ranking order:

1. Skill Lift.
2. Hard-Fail Reduction.
3. EOS-enabled mean score.

## Integrity / 完整性

- Structural CI validates files, headings, provenance fields, and anti-fabrication constraints.
- Structural CI is not semantic model evaluation.
- LLM-assisted scoring may help, but cannot be the sole final evaluator for a Verified result.
- Historical submissions are immutable; configuration changes create new run IDs.
- No numeric leaderboard result is published without auditable run artifacts.

## Non-goals for v0.4

- No paid-provider runner in core CI.
- No fake seed scores.
- No automatic “LLM judge = truth”.
- No claim that public historical cases are contamination-resistant.
- No leaderboard that hides runtime configuration.

## v0.5 direction

- Hidden holdout cases.
- Provider adapters and reproducible batch runner.
- Bootstrap confidence intervals.
- Blind adjudication.
- Domain-specific sub-leaderboards.
