# v0.4 Empirical Benchmark Implementation Plan

> **For agentic workers:** execute task-by-task with verification after each task.

**Goal:** Add source-grounded real-world cases, paired NATIVE vs EOS_ENABLED run records, validation, and a reproducible Skill-Lift leaderboard without publishing unexecuted scores.

**Architecture:** Keep the Markdown-first benchmark as the case layer. Add a provenance-aware real-world set, immutable run-record contract, and leaderboard that separates raw model ability from EOS Skill lift.

**Tech Stack:** Markdown, YAML, Bash, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-28-v0.4-empirical-benchmark-design.md`

## Global Constraints

- Never publish a benchmark score that was not actually executed and scored.
- Official EOS effectiveness requires paired NATIVE and EOS_ENABLED conditions.
- Real-world cases must cite public attributable sources.
- Preserve raw outputs and per-case scorecards.
- Structural CI must not be presented as semantic model evaluation.
- Keep paid provider dependencies out of core CI.

### Task 3: Skill-Lift leaderboard

Create `leaderboard/` with Candidate/Verified eligibility, Skill Lift, Hard-Fail Reduction, and submission provenance requirements.

Verification: public README explicitly states `No verified submissions yet` until real runs exist.

### Task 4: Anti-fabrication CI

Create `scripts/validate-v04.sh`, `scripts/test-validate-v04.sh`, and `.github/workflows/validate-v04.yml`.

Required negative test: inject a fake numeric leaderboard row without run artifacts and confirm validation fails for the expected reason.
