# v0.5 Pilot Runner Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build, test, execute, score, and publish one auditable Candidate-level NATIVE vs EOS_ENABLED experiment on `Qwen/Qwen3-8B` across the five v0.4 public real-world cases.

**Architecture:** Keep generation, validation, scoring, and publication separate. A Python runner parses committed cases and the canonical EOS runtime, generates paired outputs with one pinned Hugging Face model revision, persists raw artifacts immediately, and validates treatment isolation before any score is aggregated. Paid inference runs only once through Hugging Face Jobs after all offline tests pass.

**Tech Stack:** Python 3.11, pytest, PyYAML, huggingface_hub, transformers, accelerate, PyTorch, Hugging Face Jobs, Markdown/YAML, Bash, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-05-v0.5-pilot-runner-design.md`

## Global Constraints

- Model repository is exactly `Qwen/Qwen3-8B`; execution pins an exact Hugging Face commit SHA.
- Pilot scope is exactly 5 cases × 2 conditions × 1 trial = 10 generations.
- Conditions are `NATIVE` and `EOS_ENABLED`; only the EOS Skill bundle is the intentional treatment difference.
- Baseline system prompt is the exact text defined in the spec; do not weaken it.
- Case prompts expose only Context, Evidence, and Prompt. Expected reasoning, Forbidden shortcuts, Decision criteria, Evaluation notes, and Source provenance are hidden from generation.
- EOS treatment uses exact committed canonical runtime Markdown, sorted by path, with no manual summarization.
- Default generation is deterministic: `do_sample=false`, `temperature=null`, `top_p=null`, `seed=42`, `max_new_tokens=1800`.
- No tools or web access are available to the model during answer generation.
- Generation and scoring are separate stages.
- Core CI launches no paid inference.
- One approved paid pilot job does not authorize an automatic second paid retry or larger hardware.
- Pilot output is Candidate / Pilot only; Verified remains false.
- No public numeric result is written until all 10 raw outputs, scorecards, and aggregate validations exist.

## Review Focus

1. **Case section ambiguity:** a case containing a hidden heading inside body text must not leak evaluation sections; Task 1 adds a parser boundary test.
2. **Skill bundle nondeterminism:** filesystem traversal order must not change bundle text/hash; Task 2 adds shuffled-creation-order fixtures.
3. **Treatment drift:** model revision, generation settings, case snapshot, runtime versions, or baseline prompt must not differ between NATIVE and EOS_ENABLED; Task 3 adds pair-drift parameterized tests.
4. **Partial paid run:** 9/10 outputs or a crash after several cases must remain recoverable but ineligible for Candidate publication; Task 4 adds partial-output validation tests and Task 5 persists after every generation.
5. **Score tampering:** summary arithmetic or Verified labels must not override underlying scorecards/manifests; Task 6 recomputes aggregates from scorecards and Task 7 tests publication eligibility.
